# 발굴 승격 게이트에 판단 근거를 넣는다 — 설계

> 2026-08-12 · 브레인스토밍 산출물
> 선행 완료: `75cf5e6`·`06d0c07`·`e6d8acd` (fwd 백필 따라잡기 — 이 설계의 **측정 기반**)

## 1. 발단

"승격된 종목이 시간이 지나도 워치리스트에서 빠지지 않는다. Drop 로직이 있는가?"

조사해 보니 Drop 로직은 `WATCH_TOTAL_CAP = 30` 하나뿐이고, 현재 26/30이라 **한 번도
작동한 적이 없다.** 07-22에 승격된 종목이 3주째 남아 있다.

그런데 사용자가 방향을 바꿨다:

> "일단 승격된 종목이 정말 계속 관찰이 필요한지? 먼저 근거를 찾아야 하지 않습니까?
> 현재 승격된 종목들을 살펴보니 단지 지표를 가지고 판단하는 게 가장 커 보입니다."

Drop은 **증상**이고 승격 품질이 **원인**이라는 지적이다. 그 방향으로 리서치했다.

## 2. 리서치 결과 — 승격은 지표만 본다

### 2.1 발굴 4전략이 전부 기술적/수급이다

```
momentum · pullback · flow · meanrev
```

펀더멘탈·뉴스·호재는 하나도 없다 (`services/discovery/ranker.py`의 `DEFAULT_REGIME_WEIGHTS`).

### 2.2 LLM 리뷰가 받는 것이 이게 전부다

`_build_llm_messages`(ranker.py:534)가 만드는 프롬프트 전문:

```
종목: 지엔씨에너지(119850)
레짐: neutral
레짐가중 종합점수: 0.6031 (문턱 0.55)
전략별 원점수(0~1): momentum=0.712, pullback=0.588, flow=0.443, meanrev=0.201
종가: 8,420
발굴 랭킹: #3
```

그리고 시스템 프롬프트가 **명시적으로 제약한다**:

> "아래 **정량 팩터 요약만** 근거로 이 종목이 신규 관심종목 등록 후보로 적합한지 판단하라."

LLM은 종목명과 숫자 4개만 보고 `{"suitable": bool}`을 답한다. 회사가 무엇을 하는지,
실적이 어떤지, 무슨 뉴스가 있는지 한 줄도 없다.

### 2.3 구조가 거꾸로다

| 데이터 | 시스템에 있는가 | 승격에 쓰이는가 | 토론에 쓰이는가 |
|---|---|---|---|
| PER·PBR·EPS·BPS·시총 | ✅ Kiwoom (`models.py:85-90`) | ❌ | ✅ `FundamentalDiscussionAgent` |
| 뉴스·감성 | ✅ `services/news/` | ❌ | ✅ `SentimentAgent` |
| 지표 4종 | ✅ | ✅ **이것만** | ✅ |

```
발굴: 지표 4개 + LLM(종목명 + 숫자)      ← 펀더멘탈·뉴스 없음
   ↓ 승격
토론: technical + fundamental(PER 669배!) + sentiment + risk
   → HOLD/NO_ACTION → 다음날 또 → 21일간 24회
```

**승격 게이트가 걸러야 할 것을 토론이 매일 다시 걸러내고 있다.** 그것도 LLM 4에이전트를
태워가며. 오래된 6종이 소비한 토론이 **190회**다.

## 3. 기각된 설계 — 밸류에이션 하드 필터

처음에 `PER > 50 제외`를 제안했다. 근거는 "PER 50 초과 6종이 전부 BUY 0"이었다.

**사용자가 반론했고, 데이터가 그 반론을 지지했다:**

> "실제로 시장 상황 및 센티먼트, 펀더멘탈이 강하고 강세장이면 이것을 무시하고 급등하는
> 경우가 있습니다."

`discovery_candidates`의 실제 수익률:

| 종목 | PER | fwd_1d | fwd_5d |
|---|---|---|---|
| 475150 SK이터닉스 | **57.89** | **+30.0%** | −29.92% |
| 214450 파마리서치 | 28.71 | +9.9% | +11.82% |
| 119850 지엔씨에너지 | 19.85 | −14.44% | +12.3% |
| 058610 에스피지 | **272.44** | | +3.03% |
| 108490 로보티즈 | **669.53** | | +2.27% |
| **317400 자이에스앤디** | **12.06** | −8.36% | **−32.48%** |

**PER 57.89 종목이 승격 다음날 +30% 급등했다.** 제안한 필터가 그것을 잘랐을 것이다.
정반대로 **가장 싼 종목(PER 12.06)이 5일 만에 −32.48%** 로 최악이었다.

밸류에이션과 성과 사이에 상관이 보이지 않는다. **"BUY 0 = 낭비"는 잘못된 프레이밍이었다** —
우리 시스템이 안 샀다는 것과 기회가 없었다는 것은 다른 말이다.

→ **하드 필터를 넣지 않는다.**

## 4. 결정 — 재료를 늘리고 판단은 LLM에

지금 LLM은 **판단할 근거가 없는 상태에서** `suitable`을 답하라고 요구받고 있다.
근거를 준다.

```
발굴 스캔 (2,653종)
   ↓ 4전략 → composite → 랭킹
   ↓
[신규] enrich(top_n=25)
   ├─ U1 Kiwoom ka10001 → PER·PBR·EPS·시총
   └─ U2 services/news → 7일 헤드라인 ≤5건 + 감성
   ↓
U3 llm_review_top ← 재료를 실은 프롬프트
   ↓
promote_candidates (기존 게이트 그대로)
   ↓
U4 원장에 재료와 LLM 판단 근거를 함께 기록
```

**왜 top 25인가**: 후보는 수천 개인데 Kiwoom은 **~1.4 req/s**다. 기존
`llm_review_top(top_n=25)`가 이미 상위 25개만 LLM에 보내므로 같은 집합에만 재료를 붙이면
하루 25회 호출로 끝난다. (2026-08-12에 22종을 0.8초 간격으로 조회했다가 `ka10001` 초과가
실제로 났다 — **간격 1.0초 이상**이 필요하다.)

## 5. 구현 단위

순서: **U4 → U1 → U2 → U3 → U5**. 측정 그릇을 먼저 만들어야 "언제부터 데이터가 있는지"가
명확하다.

### U4 — 원장 측정 컬럼

`discovery_candidates`에 추가:

| 컬럼 | 용도 |
|---|---|
| `per` · `pbr` · `market_cap` | 밸류에이션과 fwd 수익률의 상관을 나중에 실측 |
| `news_count` | 호재 유무가 실제로 유효한지 |
| `llm_rationale` · `llm_confidence` | LLM이 **무엇을 근거로** 통과/반려했는지 (지금은 버려진다) |

측정 없이는 이 작업 전체가 무의미하다. 지금 원장은 `composite`와 `skip_reason`만 남긴다.

⚠️ **기존 테이블에 컬럼을 더하는 것**이라 `CREATE TABLE IF NOT EXISTS`로는 생기지 않는다.
`ALTER TABLE ... ADD COLUMN`을 멱등하게(이미 있으면 무시) 실행해야 하고, 라이브
`storage.db`에는 이미 43건의 승격 이력이 있다 — **기존 행은 NULL로 남는다.** 그래서
"값이 없다"가 두 가지 뜻(U4 이전 행 / 수집 실패)을 갖는데, `trade_date`로 구별할 수 있으므로
컬럼을 더 만들지 않는다. 배포일을 이 문서에 남긴다.

### U1 — 펀더멘탈 수집기

```python
async def enrich_fundamentals(candidates, *, top_n=25, fetch=None) -> None
```

- 랭킹 상위 `top_n`만, **종목당 1회**
- `fetch`는 주입형 — 나중에 Kiwoom → 토스로 교체하거나 `warnings`를 추가할 때 여기만 바꾼다
- never-raise. 실패한 종목은 값이 `None`으로 남고 **탈락시키지 않는다**
- **`fetch=None`이면 수집을 통째로 건너뛴다**(값이 전부 `None`). 기본 구현을 몰래 끌어오지
  않는다 — `_catch_up_missed_slots`가 `close_on_date=None`을 다루는 방식과 같다. 프로덕션
  구현은 U5(배선)가 주입한다. 이렇게 나눠야 U1을 라이브 API 없이 테스트할 수 있고,
  배선이 빠졌을 때 조용히 도는 대신 **아무것도 안 하는 것이 드러난다.**
- 조회 간격 **1.0초 이상**(2026-08-12 실측: 0.8초는 `ka10001` 초과를 유발했다)

### U2 — 뉴스 수집기

```python
async def enrich_news(candidates, *, top_n=25, days=7, max_items=5, fetch=None) -> None
```

- `services/news`(naver) 재사용. **감성 점수는 만들지 않는다** —
  `analyze_stock_news_sentiment`는 종목당 LLM을 1회 더 태워 top 25면 **+25회**이고 EOD
  체인(약 65분)이 그만큼 길어진다. 헤드라인을 승격 LLM이 직접 읽게 하면 호출이 늘지 않고
  중간 요약으로 인한 정보 손실도 없다. 따라서 U4에 `news_sentiment` 컬럼도 만들지 않는다.
- EOD 체인이 그만큼 길어진다(현재 약 65분) — 헤드라인 상한으로 억제

### U3 — 프롬프트 확장

**시스템 프롬프트를 반드시 교체한다.** *"정량 팩터 요약만"* 이 한 줄이 새 재료를 무력화한다.

새 프롬프트가 담을 것:
- 밸류에이션을 **단독 배제 사유로 쓰지 말 것** — §3의 실측을 근거로 명시
- **재료 부재를 부정 신호로 읽지 말 것** — `flow`가 이미 쓰는 관행("미가용 — 부정신호 아님")을 확장
- 보수 기조("확실하지 않으면 반려")는 유지

사용자 프롬프트에 추가되는 블록:

```
[밸류에이션]  PER 57.89 · PBR 6.51 · EPS 1,234 · 시총 1.2조
              (업종 평균 PER 12~15배 / PBR 1.0배 — 참고치)

[최근 뉴스]  7일 이내 최대 5건
  08-10  "SK이터닉스, 태양광 EPC 3,000억 수주"     감성 +0.7
  감성 평균 +0.42 (5건)  |  없으면: "최근 7일 뉴스 없음 — 부정신호 아님"
```

### U5 — 배선

orchestrator가 U1·U2를 호출한 뒤 `llm_review_top`에 전달한다.

## 6. 테스트 전략

2026-08-12에 실제로 밟은 함정을 그대로 가드로 만든다:

| 가드 | 이유 |
|---|---|
| 종목당 조회 1회, `top_n` 초과 없음 | 22종 조회로 `ka10001` 초과가 실제로 났다 (`_CountingKiwoom` 패턴) |
| PER `None`인 종목이 **탈락하지 않는다** | 재료 부재 ≠ 부정 신호 |
| 시스템 프롬프트에 "정량 팩터 요약만"이 **없다** | 그 한 줄이 새 재료를 무력화한다 |
| orchestrator가 enrich 결과를 **실제로 넘긴다** | 주입이 빠지면 예외도 로그도 없이 사라진다 (C-2에서 겪음) |
| 수집 실패가 EOD 체인을 죽이지 않는다 | never-raise |

## 7. 범위 밖 — 토스 `warnings`

토스증권 Open API 조사(`docs/TOSS_OPENAPI_GUIDE.md`, `f0c37a0`)에서 나온 것:

> `warnings` — 투자경고·투자위험·단기과열·**정리매매**·VI

밸류에이션과 **성질이 다르다.** PER 필터는 "강세장이면 무시하고 급등한다"는 반론에
무너졌지만, 정리매매·투자위험은 그 반론이 성립하지 않는다. **하드 차단이 정당한 유일한
신호**로 보인다.

그럼에도 이번 범위에서 뺀다:
- 토스 API는 코드가 한 줄도 없다(인증·IP 화이트리스트·클라이언트 전부 신규)
- IP 화이트리스트 실패는 `403 edge-blocked`로 오는데, 넓은 `except`가 그것을 "데이터 없음"으로
  삼키면 **2026-08-07 계열의 사고**(데이터 실패가 방어를 풀던 것)가 된다

U1의 `fetch`를 주입형으로 두는 것이 이 확장의 접합부다.

## 8. 미해결 / 위험

- **효과를 아직 측정할 수 없다.** `fwd_20d`는 0건이고(가장 오래된 승격이 16거래일 경과 —
  정상이다) `fwd_5d`도 23건뿐이다. 첫 `fwd_20d`는 **2026-08-19경**에 채워진다.
  U4가 그때부터 상관을 재는 그릇이 된다.
- **뉴스가 EOD 체인을 얼마나 늘릴지 미측정.** 25종 × 조회 + 감성 분석. 현재 체인이 65분이고
  16:35에 끝나는데, 늘어나면 그만큼 밀린다.
- **표본이 작다.** 승격 43건, PER 분포 22종. 어떤 재료가 유효한지는 몇 주 더 모아야 안다.
  이 설계는 "판단 재료를 준다"까지이고 "무엇이 유효한지"는 U4가 답할 질문이다.
- **워치 Drop은 여전히 미해결.** 이 작업은 **유입**을 개선한다. 이미 들어와 있는 26종과
  앞으로도 쌓일 종목의 **퇴출** 규칙은 별도 설계가 필요하다. 다만 승격 품질이 오르면
  Drop의 시급성은 낮아진다.

## A.2 추가 구현 단위

기존 U1~U5(펀더멘탈·뉴스)는 그대로 두고 뒤에 붙인다. 서로 독립이다.

### T1 — 토스 클라이언트 (선결)

`backend/services/toss/client.py` 신규.

- OAuth 토큰 캐시(24h, 만료 5분 전 갱신)
- `Authorization: Bearer` 자동 부착
- 🔴 **`403`을 다른 실패와 반드시 구별한다.** IP 화이트리스트가 깨지면 전 API가 403이 되는데,
  넓은 `except`가 이것을 "데이터 없음"으로 삼키면 **2026-08-07 계열의 사고**(데이터 실패가
  노출도 상한을 두 배로 열던 것)가 된다. 403은 전용 예외 `TossIpBlockedError`로 올리고
  로그·Telegram에 명시적으로 남긴다.
- 레이트리밋: MARKET_DATA 15/s · CHART 20/s (Kiwoom ~1.4/s의 10배). 그래도 클라이언트가
  자체 스로틀을 갖는다 — 한도를 문서값 그대로 믿지 않는다.

### T2 — `index_daily` 소스 교체

### T3 — 승격 게이트 `warnings` 하드 차단

**밸류에이션 하드 필터는 §3에서 기각됐지만 시장경보는 성질이 다르다.**
"강세장이면 무시하고 급등한다"는 반론이 **정리매매·투자위험에는 성립하지 않는다.**

- 관측만: 단기과열 · VI (프롬프트에 싣되 차단하지 않음)
- `skip_reason="market_warning:<코드>"`로 원장에 남긴다 — **왜 걸렀는지가 사후에 보여야 한다**
- 🔴 **조회 실패는 차단하지 않는다(fail-open).** 403/타임아웃으로 후보가 전멸하면 그날 승격이
  0이 되는데, 그것이 "안전"이 아니라 "발굴 정지"다. 단, 실패는 `degraded`에 남긴다.
