# 유동성 인지 발굴·사이징 재설계 (Liquidity-Aware Discovery)

- 작성일: 2026-07-27
- 상태: 설계 승인 대기
- 기원: 사용자 문제제기 — "빅솔론 포지션을 보니 주가는 올랐으나 거래량·거래대금 수급이 빈약하다. 보통 이런 걸 잡주라고 한다. 종목 발굴·포지션 결정에 다양한 매매법을 리서치해 개선할 필요가 있어 보인다."

## 1. 배경 — 문제의 실체

사용자 제기를 코드와 라이브 데이터로 검증한 결과, 직관이 정확했고 원인은 예상보다 구조적이었다.

### 1.1 현상

2026-07-23 EOD 발굴이 승격한 5종의 실측 일평균 거래대금(ADTV, 20일 중앙값):

| 종목 | ADTV 중앙값 | 최소일 | 포지션 2천만원 참여율 |
|---|---:|---:|---:|
| 093190 빅솔론 | 1.2억 | 0.3억 | **16.1%** |
| 214260 라파스 | 3.4억 | 0.2억 | 6.0% |
| 094840 슈프리마HQ | 5.3억 | 0.6억 | 3.8% |
| 317400 자이에스앤디 | 21.9억 | 12.1억 | 0.9% |
| 089860 롯데렌탈 | 22.7억 | 5.7억 | 0.9% |

한국 퀀트 실무 표준 참여율은 0.5%(《현명한 퀀트 투자자》), 기관 스트레스 청산 상한은 ADV의 5%다. 빅솔론은 표준의 32배, 스트레스 상한의 3배였다.

라이브 실증도 일치한다. 07-24 빅솔론 매수는 **1,786주(₩14.9M) 주문이 655주만 체결**됐고, 07-27 매도 437주는 **당일 거래량의 5.4%**였다.

### 1.2 근본 원인 — 저유동성을 "능동적으로 선호"하는 두 메커니즘

필터가 없는 게 아니라 역선택 장치가 있다.

**(a) `factors.py:232` momentum 거래량 성분의 스케일 불변성**

```python
vol_ratio = mean(volume[-5:]) / mean(volume[-20:])
vol_component = clamp01(vol_ratio - 1.0)
```

0차 동차 함수라 절대 유동성 정보를 100% 소거한다. 분모가 작을수록 만점을 받기 쉬워 ADTV 3억 종목이 ADTV 3,000억 종목보다 구조적으로 유리하다. 하방에도 무감각해서 `vol_ratio` 0.3과 1.0이 똑같이 0점이며, **"거래량 급감 중 상승"이라는 가장 위험한 패턴에 페널티가 정확히 0**이다.

빅솔론 실측: `vol_ratio 0.81`(거래량 감소 중)인데 나머지 3성분이 만점이라 momentum 0.748을 받았다.

**(b) `ranker.py:351` `_effective_weights`의 flow 결측 재정규화 — 편향의 증폭기**

`ka10131` 수급 랭킹은 상위 약 100행만 수집되므로 소형주는 정의상 전부 `flow_present=False`다. 이때 flow 가중이 나머지 3전략에 재분배된다.

bullish 레짐 실측: `{momentum .40, pullback .25, flow .25, meanrev .10}` → scale = 1.0/0.75 = 1.333 → **momentum 가중이 .40에서 .533으로 33% 증폭**된다.

즉 유동성이 가장 의심스러운 종목 집단에서만 선택적으로, 이미 저유동성을 선호하는 전략의 가중치가 자동으로 커진다. 두 메커니즘의 곱이 "최근 승격 종목이 전부 momentum"이라는 관측의 결정론적 원인이다.

**(c) 유동성 필터 부재**

`passes_quality_filter`(factors.py:99)는 `price>0`, `market_cap≥500억`, `len(chart_df)≥60`만 검사한다. 시가총액은 한국에서 유동성 대리변수로 작동하지 않는다 — KOSPI 947곳 중 50.5%가 ADTV 10억 미만이다(아주경제 2026-06). KRX 자신의 KOSPI200조차 시총과 별개로 "산업군 내 일평균거래대금 하위 15% 배제" 유동성 컷을 둔다.

### 1.3 하류 방어선은 원리적으로 무력하다

LLM 검토도 4에이전트 토론도 프롬프트에 들어온 정보만 판단한다. ADTV·참여율·청산소요일수는 수집 단계에서 **계산조차 되지 않으므로** 리스크 에이전트는 그 사실의 존재를 모른다. 따라서 투표 합의 문턱을 0.75에서 0.85로 올려도 이 유형의 오류는 한 건도 걸러지지 않는다. **반드시 상류에서 고쳐야 한다.**

### 1.4 수정 비용이 거의 없다

`client.py:687-690`이 `ka10081` 일봉 응답의 `trde_prica`(거래대금, 백만원 단위)를 이미 파싱해 `ChartData.acml_tr_pbmn`에 원 단위로 담고 있다. 그런데 `get_daily_chart_df`(client.py:787-796)가 DataFrame 변환 시 `date/open/high/low/close/volume` 6개만 뽑고 **이 필드를 버린다**. 한 줄을 추가하면 종가×거래량 근사가 아닌 **거래소 실측 거래대금**이 파이프라인 전체에 흐른다.

## 2. 실측 검증 — 임계값 근거

리서치가 "절대 하지 말아야 할 것: 임계값을 실측 없이 배포하는 것"을 명시했으므로, 배포 전 검증을 설계 단계에서 완료했다.

### 2.1 후보 고갈 위험 (2026-07-23 배치, bullish, 2,649종)

문턱 0.55 통과 80종의 ADTV 분포: 하위10% 1.3억 / 25% 3.3억 / **중앙값 6.7억** / 75% 41.4억.

| ADTV 컷 | 생존 (현 랭킹 80종) | 생존 (재정규화 폐기 후 17종) |
|---|---:|---:|
| 10억 | 34종 (42%) | 14종 |
| **20억 (참여율 1%)** | 27종 (34%) | **13종** |
| 30억 | 21종 (26%) | 9종 |
| 50억 | 17종 (21%) | 8종 |

**daily_cap 5종 대비 어느 컷에서도 여유가 있다. 고갈 위험 없음.**

### 2.2 재정규화 폐기의 효과 — 단독으로도 저유동성 3종 제거

base 가중(재분배 없음)으로 composite 재계산:

| 종목 | 기존 | 폐기 후 | ADTV | 결과 |
|---|---:|---:|---:|---|
| 자이에스앤디 | 0.6898 | 0.6898 | 21.9억 | 무변화 (flow_present=True) |
| 롯데렌탈 | 0.6699 | 0.6699 | 22.7억 | 무변화 |
| 슈프리마HQ | 0.6471 | **0.4853** | 5.3억 | 탈락 |
| 라파스 | 0.6379 | **0.4784** | 3.4억 | 탈락 |
| 빅솔론 | 0.6360 | **0.4770** | 1.2억 | **탈락** |

`flow_present=True` 종목은 점수가 전혀 변하지 않는다(재정규화가 결측 종목만 부풀렸다는 직접 증거). **재정규화 폐기만으로 상위 17종의 82%가 ADTV 10억 이상이 된다** — 기존 80종에서는 42%였다. 수급 랭킹 진입 자체가 유동성의 대리 검증으로 작동한다.

### 2.3 실측으로 기각한 리서치 권고 2건

- **threshold 재산출 불필요**: 리서치는 "재정규화 폐기는 threshold 재산출과 반드시 세트"라고 했으나, 문턱 0.55 유지 시 17종이 통과해 daily_cap 5의 3.4배다. 재산출 없이 작동한다.
- **"momentum 단독 승격 금지" 불필요**: 문턱 0.55에서 적용 전후 17종 → 17종으로 효과가 정확히 0이다. 통과 종목이 전부 `flow_present=True`라 조건이 발동조차 하지 않는다. YAGNI로 제외한다.

## 3. 설계

### 3.1 개입 지점

```
[수집]     client.py     : trde_prica → chart_df "value" 컬럼          ← A0 (전제)
[품질필터] factors.py    : 참여율 게이트 + 하방 일관성 + 저가주 배제     ← A1
[전략스코어] factors.py  : momentum 거래량 성분 교체 + 고가근접 재스케일  ← A2
[랭킹가중] ranker.py     : _effective_weights 재정규화 폐기             ← B
[사이징]   r_sizing.py   : 참여율 캡 min(4%, R-cap, ADTV×0.5%)         ← C1
[LLM/토론] 프롬프트      : 유동성 사실 주입 + 리스크 판정 기준            ← C2
```

### 3.2 A0 — 거래대금 배선 (전제)

`get_daily_chart_df`의 dict comprehension에 `"value": c.acml_tr_pbmn` 추가. `acml_tr_pbmn`이 `None`인 행은 `close × volume` 폴백(구 캐시 호환). 이 컬럼이 이후 모든 계산의 입력이다.

### 3.3 A1 — 유동성 게이트 (참여율 기반)

`passes_quality_filter`에 키워드 인자 `min_adtv: float`를 추가하고 다음을 AND로 검사한다:

1. `ADTV20_med = median(value[-20:]) >= min_adtv`
2. 하방 일관성: `count(value_d < min_adtv * 0.6) <= 5` (20일 중 15일 이상 통과, MSCI FoT 80%의 일간 이식)
3. 거래량 0인 날이 1일이라도 있으면 배제
4. `close >= 2,000원` (호가단위 마찰 상한 0.25% + 동전주 퇴출 리스크)

**평균이 아니라 중앙값을 쓰는 이유**: 모멘텀 전략은 정의상 급등일을 포함하므로 평균이 체계적으로 상향 편향된다. MSCI ATVR과 FTSE GEIS가 유동성 스크린에 median을 채택한 근거와 동일하다.

**`min_adtv` 산출** — factors.py는 순수 함수를 유지하고 호출자(scanner.py:1054)가 계산해 주입한다:

```python
position_notional = equity * 0.04          # 현 배분 정책
min_adtv = max(position_notional / 0.01,   # 참여율 1% 게이트
               1_000_000_000)              # 하드플로어 10억 (절대 불변)
```

계좌 5억 기준 `min_adtv = 20억`. 계좌 규모가 바뀌면 자동 조정된다. **계좌 조회 실패 시 폴백은 설정값 `DISCOVERY_MIN_ADTV_FALLBACK`(기본 20억)** — fail-closed(조회 실패가 게이트 완화로 이어지지 않음).

사유 코드 `REASON_LIQUIDITY_LOW`를 신설해 기존 `skip_reason` 관용구를 따른다.

### 3.4 A2 — momentum 거래량 성분 교체

`_extract_atoms`가 `chart_df["value"]`에서 다음 원자를 계산해 `atoms`에 추가한다(기존 원자와 동일하게 데이터 부족 시 `None`):

```python
adtv20_med = median(value[-20:])                    # 게이트·사이징·프롬프트 공용
value_ratio = mean(value[-5:]) / mean(value[-20:])  # 거래'대금' 기준 상대 확장
value_surge = mean(value[-5:]) / mean(value[-60:])
```

`ADTV20_med`는 이렇게 **`chart_df`에서 계산**되며, §3.3의 `min_adtv`(계좌 기반 임계값)와는 별개다 — 전자는 종목의 실측 유동성, 후자는 통과 기준선이다.

```python
liq_gate = clamp01(log10(adtv20_med / 10억) / log10(10))   # 10억=0.0, 100억=1.0
rel      = clamp01(value_ratio - 1.0)
vol_component = liq_gate * rel * (0.0 if value_surge >= 5.0 else 1.0)
```

곱셈 게이트가 핵심이다 — 절대 유동성이 하한이면 상대 급증이 아무리 커도 0점이다. `value_surge >= 5.0` 상한은 펌프·작전(실무 세력 판별선 "평균 대비 3배"의 5일 평활 버전)과 한국 MAX 효과(고MAX 종목 월 -1.87~-1.94%p, JDQS 29(1))를 동시에 차단한다.

기존 `volume`(주) 기준을 `value`(원) 기준으로 바꾸면 저가주가 이중으로 유리하던 편향도 사라진다.

**A1 게이트와의 관계**: A1을 통과한 종목(계좌 5억 기준 ADTV ≥ 20억)은 `liq_gate ≥ 0.30`이 된다. 즉 게이트는 자격을, `liq_gate`는 통과 이후의 **유동성 차등**을 담당한다. 중복이 아니라 계층이다.

### 3.5 A3 — 20일 고가근접 무상점수 제거

```python
high20_prox_score = clamp01((current / high20 - 0.90) / 0.10)   # 90% 미만 0점, 신고가 1.0
```

현 `clamp01(current/high20)`은 정상 종목에서 0.85~1.00에 상시 분포해 momentum 4성분 평균에 약 0.22의 바닥 점수를 무조건 깔아준다. 문턱 0.52~0.55에서 이는 결정적이다. 재스케일로 실질 변별력을 회복한다.

추가로 이 성분에 거래량 확인 계수를 곱한다: `* (1.0 if value_ratio >= 1.2 else 0.5)` — `value_ratio`는 §3.4에서 정의한 거래대금 상대 확장이다. 거래량 확장 없는 고가 근접(Wyckoff no-demand)에 절반 페널티를 준다.

### 3.6 B — flow 결측 재정규화 폐기

`_effective_weights`에서 `flow_present=False`일 때 **재분배를 하지 않는다**. flow 자리는 0으로 두고 composite가 자연히 낮아지게 한다. 수급 미확인을 "정보 부재"가 아니라 **"검증 실패"**로 취급한다.

- threshold는 **0.55 유지**(§2.3 실측 근거).
- "momentum 단독 승격 금지" 규칙은 **도입하지 않음**(효과 0, YAGNI).
- 함수 시그니처와 `flow_present=True` 경로는 불변 → 하위 호환.

`_effective_weights`는 재분배 로직이 사라지면 사실상 항등 함수가 되지만, 호출부 시그니처와 STRATEGIES 밖 키 통과 규약을 유지하기 위해 함수는 남기고 내부만 단순화한다(호출부 수정 최소화).

### 3.7 C1 — 유동성 반응형 사이징 캡

`r_sizing.py`의 기존 `min()` 체인에 항을 추가한다:

```python
max_notional = min(equity * 0.04,
                   r_cap_value(...),           # 기존 R-사이징 (risk_budget 0.75%)
                   ADTV20_med * 0.005)         # 참여율 0.5% (실무 표준)
```

계좌 5억 기준: ADTV 40억↑ → 2,000만원 / 30억 → 1,500만원 / 20억 → 1,000만원.

**하한 스킵**: `max_notional < equity * 0.01`(500만원)이면 진입을 포기한다. 소액 포지션은 체결단위 미달과 고정 수수료·호가단위 마찰의 상대 비중 증가로 실효 비용률이 오히려 올라간다.

**주문 직전 재계산 필수**: 승격 시점(EOD)과 진입 시점(워치 트리거, 수일 후) 사이에 유동성이 급변할 수 있다.

게이트(1%)와 사이징(0.5%)의 2계층 구조다 — 게이트는 진입 자격, 사이징은 실제 크기.

### 3.8 C2 — 유동성 사실 전파

A1·C1이 계산한 값을 `factor_json → 워치 레코드 → 토론 프롬프트`로 전파한다. 리스크 에이전트 프롬프트에 명시할 필드: `ADTV20_med`, 참여율, 예상 왕복비용, `flow_present`(수급 미확인 여부).

판정 기준을 명문화한다: **"참여율 > 1%이면 반대표를 던질 것."**

US 신호를 심리/리스크 프롬프트에 전파해 라이브 소비 확증(402340 사례)을 받은 전례와 동일 패턴이다. 로컬 LLM의 컨텍스트 부담을 고려해 **6개 필드를 한 줄 요약 문장으로 압축**한다.

**이것은 §1.3의 하드 게이트 뒤에 놓는 보조 방어선이며, 단독 방어선으로 취급하지 않는다.**

## 4. 정당화 논거 — 알파가 아니라 실행비용

유동성 필터를 "수익률이 오른다"로 정당화하지 않는다. Bulkowski 실측상 돌파 전 거래량 추세 효과는 34% vs 31%로 modest하고, 한국 이식 가능성도 미검증이다. 청산 실적 표본이 사실상 3건인 현 시스템에서 알파 주장은 검증 불가능하다.

정당화는 **실행비용과 청산가능성**에서만 찾는다. 제곱근 시장충격 법칙(`impact ≈ Y·σ·√(Q/V)`)으로 추정한 왕복 총비용:

| ADTV | 왕복 비용 | 손절폭 4.5% 대비 | 실효 손익비 (설계 2.22) |
|---|---:|---:|---:|
| 3.6억 | 2.5~3.5% | 56~78% | **0.9~1.17** |
| 10억 | 1.4% | 31% | 1.6 |
| 30억 | 1.0% | 22% | 1.8 |
| 50억 | 0.8% | 18% | 1.9 |

**저유동성 종목에서는 거래비용이 손절폭의 절반 이상을 잠식해 손익비가 2.22에서 0.9로 붕괴한다.** 이것이 binding constraint다.

## 5. 테스트 전략

TDD로 진행한다. 순수 함수 중심이라 단위 테스트가 자연스럽다.

**회귀 픽스처(핵심)**: 빅솔론 093190의 실측값을 고정한다 — `ADTV20_med 1.2억`, `vol_ratio 0.81`, `flow_present False`, `composite 0.636`. 이 종목이 **반드시 탈락**하는지가 전체 설계의 수용 기준이다.

- A0: `acml_tr_pbmn` None 폴백, 컬럼 존재
- A1: 게이트 통과/탈락 경계, 하방 일관성 5일 경계, 거래량 0일, 저가주, `min_adtv` 폴백(fail-closed)
- A2: `liq_gate` 로그 스케일 경계(10억=0, 100억=1), `surge≥5.0` 차단, 곱셈 게이트(고 rel + 저 liq = 0)
- A3: 재스케일 경계(0.90 미만 0점), 거래량 확인 계수
- B: `flow_present=True` 무변화(하위호환), `False` 시 재분배 없음, 실측 5종 재현
- C1: `min()` 체인 순서, 하한 스킵, 주문 직전 재계산
- C2: 프롬프트 필드 존재, `None` 안전(값 없으면 문장 생략)

기존 discovery 스위트(84+ 테스트) 무회귀 확인.

## 6. 배포 순서

**A → B → C 순차 배포.** 각 단계 후 EOD 실측 분포를 확인한다.

이유: ① A만으로 사용자 제기 문제(빅솔론·라파스·슈프리마HQ)가 해결된다 ② 각 단계가 독립 검증 가능해 효과 귀속이 명확하다 ③ B는 §2.2에서 이미 실측했지만 라이브 EOD로 재확인이 필요하다.

**운용 제약**(기존 관용구 준수):
- 15:30~16:35 EOD 발굴 스캔 창에는 재시작 금지
- 실 포지션 보유 중 장중 재시작 금지
- 배포 후 `/trading/start` + `/agent-chat/start` 재발행

**킬스위치**: 기존 `DISCOVERY_*` 설정 관용구를 따라 `DISCOVERY_LIQUIDITY_GATE_ENABLED`(기본 on)를 둔다. off 시 A1 게이트만 무효화하고 A2/A3/B는 유지한다(스코어 수식은 롤백 단위가 다름).
