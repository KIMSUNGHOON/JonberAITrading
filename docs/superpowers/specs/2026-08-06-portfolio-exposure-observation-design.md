# 포트폴리오 목표 노출도 — 관측 단계 설계

- 날짜: 2026-08-06
- 범위: **관측 전용.** 매매 동작 변경 0.
- 선행 리서치: 노출도 자동조절 방법론 조사 (동일 세션)

## 1. 문제

계좌 ₩497,403,042 중 주식이 ₩49,426,800(9.9%)이고 나머지 90%가 예수금이다.
레짐 적응형 전략 체인은 이미 있고 강세장에 반응도 하고 있으나(현금 하한
0.45→0.30, 슬롯 3→8 투표), 그 노브들이 실제 배분을 결정하지 않는다.

실제 배분은 `min(available_for_trade, 종목당_천장)`으로 정해지는데 두 항이 20배
차이난다.

| 제약 | 허용액 |
|---|---|
| 현금여유 (`min_cash_ratio` 30%) | ₩300,139,688 |
| 주식여유 (`max_total_stock_pct` 80%) | ₩348,495,634 |
| **종목당 천장 (`max_single_position_pct` 3%)** | **₩14,922,091** ← 실제로 무는 것 |

`min_cash_ratio`는 87.3%를 넘어야, `max_total_stock_pct`는 12.9% 아래로
내려가야 병목이 된다. 총 노출 천장은 `슬롯 수 × 종목당 비중` = 5 × 3% = 15%이고,
슬롯 수는 `GATE_PROTECTED_FIELDS` 봉인이라 전략이 못 건드린다.

**빠진 것은 새 알고리즘이 아니라 계층 하나다.**

```
주문금액 = 목표노출도(포트폴리오) × 종목배분(R-사이징) × 실행캡(유동성·명목)
           ↑ 없음                    ↑ 있음              ↑ 있음
```

R-사이징(리스크 예산 0.75% ÷ 손절 거리)은 이미 변동성 기반 사이징의 정석이고
작동한다. 이 설계는 그 위층만 만든다.

## 2. 왜 관측부터인가

왕복 8건, 승률 50%, 손익비 0.820, 평균 −47,552 / SE 237,419 → **t ≈ −0.20**.
엣지가 음수인 게 아니라 **미측정**이다.

최소 트랙레코드 길이(정규 근사): `MinTRL ≈ (z / s)²`, `s` = 거래당 평균손익 ÷
거래당 표준편차. 현재 실측 `s ≈ −0.071`이면 약 550 왕복이 필요하고, 쓸 만한
엣지(`s ≈ 0.25`)라면 약 43 왕복이면 드러난다.

주당 약 3건이 쌓이므로 43건까지 약 3개월. **어떤 사이징 공식도 엣지 추정치를
입력으로 요구하는데 지금은 그 입력이 없다.** 그래서 이번 단계는 계산해서
기록만 하고 사이징에는 연결하지 않는다.

## 3. 구성요소

### 3.1 `services/trading/exposure_target.py` (신규, 순수 계산)

DB도 API도 모른다. 입력을 받아 목표 노출도와 성분을 돌려주는 함수 하나.

```python
compute_target_exposure(
    equity: float,
    stock_value: float,
    index_returns: list[float],   # 지수 일별 등락률(%)
    regime_label: str,            # risk_on / neutral / risk_off
    n_round_trips: int,
    equity_peak: float,
    e_base: float = 0.50,
    e_max: float = 0.30,
) -> TargetExposure
```

`TargetExposure`는 `target_pct`, 성분별 값, `binding`(최종값을 정한 성분 이름),
`degraded`(신뢰할 수 없어 중립 처리한 성분과 사유)를 담는다.

`binding`/`degraded` 패턴은 `PortfolioAgent._calculate_max_position_value`의
`lineage` out-param과 같은 계열이다 — 숫자만 남기면 나중에 "왜 이 값이었나"를
못 푼다.

### 3.2 공식

```
E = E_base × M_regime × M_vol × M_evidence × M_drawdown     (0.02 ≤ E ≤ E_max)
```

| 성분 | 정의 | 2026-08-06 값 |
|---|---|---|
| `E_base` | 증거 충분·중립 레짐·정상 변동성·무낙폭일 때 목표 | 0.50 |
| `M_regime` | risk_on 1.2 / neutral 1.0 / risk_off 0.5 | 1.0 |
| `M_vol` | `clip(18.0 ÷ σ_ann, 0.5, 1.5)` — 위생 게이트 통과 시에만 | **1.0 (게이트 탈락)** |
| `M_evidence` | `min(1, 왕복수 ÷ 40)` | 0.20 |
| `M_drawdown` | `max(0.3, 1 − 3 × 고점대비낙폭)` | 1.0 |

**단위 규약**: `σ_ann`과 목표 변동성(18.0), 위생 게이트 경계(5.0~60.0)는 전부
**퍼센트 단위**다. 셋이 같은 단위라야 `18.0 ÷ σ_ann`이 1 근처의 배수가 된다 —
목표만 소수(0.18)로 두면 결과가 100배 틀어진다.

`σ_ann` = 최근 20거래일(없으면 있는 만큼, 최소 5개) 지수 일별 등락률(%)의 표본
표준편차 × √250. 표본이 5개 미만이면 `M_vol=1.0` +
`degraded='index_vol_insufficient'`.

`M_regime`이 비대칭인 이유: 축소 오판보다 확대 오판의 비용이 크다.

현재 상태를 넣으면 `0.50 × 1.0 × 1.0 × 0.20 × 1.0 = 10.0%`이고 실제는 9.9%다.
즉 이 공식은 지금 "적정하게 실려 있다"고 말하고, 표본이 쌓이면 자동으로 열린다.

`E_base = 0.50`은 `max_total_stock_pct`(0.80)·`min_cash_ratio`(0.30)가 허용하는
70%보다 보수적으로 잡은 값이며 관측 결과를 보고 조정할 노브다.

### 3.3 🔴 변동성 입력의 위생 게이트

`regime_snapshot.index_kospi_chg_pct` 14일치의 실현 연변동성이 **112.1%**다.
지수 레벨 변화와 등락률이 서로 일치하므로 파싱 오류가 아니라 데이터 자체가
그렇게 움직인다(예: 07-28 −10.84%, 07-31 +17.91%). 계좌는 `trading_mode: paper`라
키움 모의투자 서버를 보고 있다.

**브로드 지수가 14거래일 내내 ±10~18%로 움직이는 것은 실제 시장에서 불가능하다.**
이 계열을 그대로 쓰면 모의 생성기의 잡음을 측정하게 된다.

그래서 실현 연변동성이 **5%~60%** 밖이면 입력을 신뢰하지 않고 `M_vol = 1.0`으로
두되, `degraded='index_vol_implausible'`와 **실제 계산값을 함께 기록**한다.
조용히 중립이 되는 것이 아니라 왜 중립인지가 남는다.

### 3.4 저장

**신규 테이블 `exposure_shadow`** — 5분마다 1행.

```
ts, target_pct, actual_pct, equity, stock_value,
m_regime, m_vol, m_evidence, m_drawdown,
binding, degraded, index_vol_annualized, index_vol_n, n_round_trips
```

`index_vol_n`은 실제 표본 수(현재 14). 20일 미만으로 계산했다는 사실이 행에
남아야 한다.

**기존 확장** — `daily_perf_snapshot`에 `stock_value` 컬럼 추가. 지금은 안 쓰지만,
한 달 뒤 "현금 희석을 제거한 주식 슬리브 변동성"으로 갈아타기 위한 재료를
지금부터 쌓는다.

## 4. 데이터 흐름

```
트레이딩 코디네이터 1분 tick
  → 5분 스로틀 통과? → is_krx_open_cached()?
  → 입력 수집
      equity, stock_value  ← self._state.account (이미 주기 갱신 중)
      index_returns[≤20]   ← regime_snapshot (일 1회 로드 후 캐시)
      regime_label         ← 최신 regime_snapshot
      n_round_trips        ← kr_realized_pnl을 (stk_cd, entry_at)로 접은 수,
                             stk_cd='ALL' 백필 행 제외 (일 1회 캐시)
      equity_peak          ← daily_perf_snapshot.equity 최댓값 ∪ 당일 장중 최고
  → compute_target_exposure(...)
  → exposure_shadow 1행 기록
```

코디네이터 루프에 붙이는 이유: 계좌 스냅샷·포지션·리스크 파라미터가 이미 그
루프 안에 있어 신규 배관이 가장 적고, 별도 태스크로 만들면 Kiwoom 조회가
중복된다(이 리포는 레이트리밋에 이미 한 번 데였다).

## 5. 실패 처리

**never-raise가 원칙이다.** 관측이 매매를 멈추면 본말전도다.

| 상황 | 처리 |
|---|---|
| 성분 입력 결측 | 그 성분 1.0(중립) + `degraded`에 어느 성분이 왜 빠졌는지 기록 |
| 지수 시계열 20일 미만 | 있는 만큼 계산하고 `index_vol_n`에 실제 표본 수 기록 |
| 실현 변동성이 5~60% 밖 | `M_vol=1.0` + `degraded` + 원값 보존 (§3.3) |
| 계좌 스냅샷 없음/0 | **행을 쓰지 않는다** — 0으로 채운 행은 진짜 0과 구분 불가 |
| 그 외 예외 | warning 로그 후 스킵. 코디네이터 루프로 전파 금지 |

## 6. 테스트

**순수 함수** — 각 성분이 단독으로 목표를 움직이는가(한 번에 하나만) / 위생
게이트 양방향(112% → 중립+degraded, 18% → 실제 적용) / `M_evidence` 단조성(왕복
수가 늘면 목표가 감소하지 않는다) / 결측 입력이 `degraded` 없이 통과하지 않는가 /
`binding`이 실제 최솟값 성분과 일치 / 클립 경계.

**기록 경로** — 5분 스로틀, 장외 스킵, 계좌 없을 때 행 미기록, 예외 비전파.
⚠️ `isolated_storage_service` 픽스처 필수 — opt-in 격리 없는 테스트가 라이브
`storage.db`를 덮어써 코디네이터 상태를 훼손한 사고가 실제로 있었다.

**회귀 가드** — 이 유닛의 유무와 무관하게 `calculate_allocation` 결과가 동일해야
한다. "관측 전용"이라는 계약을 코드로 못박는다.

## 7. 성공 판정 (배포 후)

이 리포의 반복 실패가 "만들어졌으나 닿지 않는다"이므로 판정 기준을 미리 쓴다.

> 장중 5분 주기면 **하루 약 78행**이 정상. **0행이면 배선 실패**이지 "발생 조건이
> 없었던" 것이 아니다 — 이 유닛은 장중이면 무조건 발생한다.

2~3주 뒤 `exposure_shadow`와 `slot_contest`를 대조해 "슬롯이 거절된 순간에 공식이
말한 여유가 얼마였는가"에 답할 수 있으면 이 단계는 성공이다. 오늘만 해도 팬오션
(028670)이 만장일치 BUY로 3회 거절됐다.

### 7.1 졸업 규칙 (사이징에 연결하기 전에)

세 조회 실패 폴백(`regime_read_failed`→`m_regime=1.0`,
`round_trips_read_failed`→`m_evidence=1.0`, `index_returns_read_failed`→
`index_vol_insufficient`→`m_vol=1.0`)은 각각 목표를 **위로** 미는 쪽으로만
치우쳐 있고, 서로 복합된다. 저장소 전체 장애(세 조회가 전부 실패)라면
`0.50 × 1.0(regime) × 1.0(vol) × 1.0(evidence) × 1.0(drawdown) = 0.50`이 나오고
`e_max`(0.30)에 clip된다 — 지금 목표(≈10~12%)의 약 3배다. 관측 전용인 지금은
기록만 되니 무해하지만, **이 유닛이 사이징에 연결되는 순간부터는
`degraded`가 비어 있지 않은 행을 사이징에 써서는 안 된다** — 이것을 졸업(사이징
연결)의 명시적 전제조건으로 못박아 둔다.

같은 이유로 `m_evidence`의 정의역은 `[0, 1]`이라 항등원 `1.0`은 "증거가 충분히
쌓였다"는 뜻이다. 조회 실패로 대체된 `1.0`은 그 반대(증거를 못 봤다)인데
숫자만 보면 구별이 안 된다 — `degraded`를 안 보고 `m_evidence`만 읽으면 정확히
반대로 해석하게 된다.

### 7.2 첫 라이브 행의 기대값

§3.2의 "10.0%" 예시는 `regime_label="neutral"`을 가정한 것이다. 실제
2026-08-05 라이브 레짐은 **`risk_on`**(`m_regime=1.2`)이다. 따라서 배포 후 첫
라이브 행은 10.0%가 아니라 `0.50 × 1.2 × 1.0 × 0.20 × 1.0 = 12.0%` 근방,
`binding="m_evidence"`, `degraded=["index_vol_implausible"]`(§3.3의 위생 게이트가
여전히 모의 지수를 걸러내는 중)로 나와야 정상이다. **10.0%가 보이면 레짐
조회(`get_latest_regime_label`)가 작동하지 않고 있다는 뜻이다** — "정상으로
보이는 값"이 실은 배선 실패의 신호일 수 있다는 점에서 5절의 실패 처리 표와
같은 함정이다.

## 8. 미해결 (범위 밖, 반드시 기록)

- **성과 기록이 모의 시장에 대한 것이다.** 지수가 모의 데이터라면 왕복 8건의
  엣지도 모의 시장에서의 엣지다. `M_evidence`가 40에 도달해도 그 사실은 변하지
  않는다. **노출도를 실제로 키우기 전에 반드시 짚어야 한다.**
- ADD는 `daily_trades_count`를 증가시키기만 하고 상한 검사는 받지 않는다.
- `_notify_add_gate_denied`에 래치가 없어 게이트 거절마다 Telegram을 보낸다.
- 재평가 가격 트리거가 `min_discussion_interval_minutes`에 막히면 49분 시계가
  통째로 새로 감긴다(2026-08-06 090430 실측: 3.2% 급등 신호가 버려짐).

## 9. 하지 않는 것

- 종목당 비중을 먼저 키우는 것 — 미측정 엣지에 배수를 곱하는 행위다.
- 현금 비율 노브 조정 — 이 계좌에서 병목이 아니다(87.3% 넘어야 효과).
- 평균-분산 최적화 — 표본 8건에 공분산을 얹으면 잡음을 최적화한다.
- 장중 노출도 **적용** — 이번 단계는 계산과 기록까지다.
